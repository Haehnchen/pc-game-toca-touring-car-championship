# Static Donington barrier contact

## Data

- `scene::BarrierData` decodes the original POINTS/LOWPOINT prefix consumed by `00479182`: uint32 route count, that many 64-byte route records, uint32 barrier count, 88-byte barrier records. `0044e7bb` supplies KEEP member1 at detail3, otherwise FREE member0. Donington: 229 barriers (67 kind0, 144 kind1, 10 kind2, 8 kind3). The decoder owns endpoints and original record identities; other route consumers keep the prefix and trailing bytes. No render mesh is used to invent walls.
- `00478d10` rebuilds each vertical plane normal from the two endpoints. Special cases compare whole-unit truncated X/Z coordinates (no float epsilon). Diagonal normal keeps the source fixed division, midpoint square root and reciprocal normalization. Counts/byte extents are checked before allocation/reads; runtime pointers and prepared coefficients from the file are not trusted.
- Source order: `0040b360` → `0040caf0` → `0040d5f0` → `00409c30`, later `00421980` → `00415240` → `0040f5c0` ground completion. Native `Motion` calls the consumer in the same position. `BarrierData`, like HPC, must outlive the borrowing Motion.

## Ordinary static path

- `00409020` → `004086b0`/`00408a00`: finite endpoints tested against the horizontal body box. Correction follows the endpoint ray from the previous body center (not a fixed outward push or infinite plane).
- `004091e0`: previous/current plane sides and velocity reject contacts moving away; original radius gate kept.
- `004093b0`/`004095b0`: eight corners classified by plane side and finite endpoint bracket; the selected exposed corner determines correction. Normal velocity changes by `mul16(normalVelocity,-0x1999)-normalVelocity`. The doubled velocity change is capped at `0x34ccc` before the local contact-arm cross product; each torque component capped at `0x1f40000`.
- Local torque is stored for the next `0040caf0` body step (source multiplies by body mass before inverse-inertia integration). Position/velocity correction is immediate; ground completion then queries corrected corners and publishes the pose.

## Original sector candidates

- `004962e0` keeps X/Z translation from every non-root terrain node, including nodes without a drawable variant. The native terrain decoder publishes these signed Q16 centers in file order. `BarrierData(route_points, sector_centers)` owns decoded records and rebuilt lists (inputs not retained).
- `0047de00` derives first-row width, minimum X, maximum Z and half the minimum adjacent same-row X spacing. `0047db40`/`0047dd30` select each sector's barriers against its rectangle expanded by `0x28000` (2.5 units): inclusive endpoint checks, outcode rejection, first endpoint's clipping-edge priority, fixed divide-then-multiply. Candidate IDs ascend in file order. The native constructor validates complete row order and 64-unit spacing required by the hardcoded shift22 lookup; malformed grids fail at load.
- `0047dab0` maps body position to column/row with arithmetic shift22 and **63 raw units** adjustment for negatives (neither float conversion nor full fixed-point truncation). `0047e370` checks grid bounds. Native out-of-grid positions return no candidates (the original caller reads an invalid negative-sector pointer); no replacement wall or scene guard.
- `00409c30` chooses the sector once before any correction, then consumes the list in reverse. `MotionState.barrier_sector` records the pre-correction index (-1 when absent). Kinds2/3 stay in candidate lists with original IDs but are not ordinary kind0/1 walls.

## Linked kind2/3 recovery

- `00479182` chains consecutive kind2/3 records through prepared field +0x4c. Exact endpoint equality joins successive records; a discontinuity, ordinary record or end of file closes the preceding circular run. Native links are bounded segment indices, reconstructed (serialized pointers not trusted). `00478d10` prepares nine line/projection coefficients (+0x24..0x44), axis class +0x50, orientation +0x54 (kind3 reverses). Diagonal preparation keeps each fixed division/multiplication, incl. the reciprocal overwritten into +0x30 after the other coefficients.
- Second reverse-candidate pass of `00409c30` tests only kind2 via `00409da0` → `00406e60` (original approach/radius and finite-corner entry predicates). Entry saves velocity and the oriented normal push ×`0x7ae`; no immediate replacement impulse. State is a `BarrierRecovery` value inside `MotionState` (active/head, primary push, saved velocity, secondary segment/push, secondary flag), so failed HPC completion rolls it back with the body.
- Next update: the active flag diverts `00409c30` into `004074a0`, bypassing sector enumeration and ordinary walls. `00406ec0` walks the whole linked run; recovery ends when all eight corners lie strictly outside any kind2 half-space. Otherwise `00406ff0` projects the body center onto finite kind2 segments, picks the strictly closest valid projection, updates the primary push. Disassembly `00407011..004071bf` confirms a source alias: the first iteration supplies a null candidate pointer while still recording its minimum distance; later iterations supply the current segment. Kept; nearest-head selection is not repaired.
- `00408040` visits kind3 members: projects the furthest forbidden corner onto the prepared line, shifts body plus existing corners, removes normal velocity and transfers its magnitude to the tangent oriented with the primary push. A repeated secondary segment restores the remembered tangent push to current and saved velocity; otherwise it records the new segment/push. Stops after the first applicable kind3 response.
- `004074a0`: caps current velocity at 1.0 (original lookup normalization), adds primary push to current and saved velocity, aligns the body basis with saved horizontal velocity. Reverse gear uses a negative normalization reciprocal. `0x199a` close threshold and `0x1999` incremental direction step kept. Up-axis projection only for positive forward dot; third axis from normalized forward/up cross product. Basis publication does not rebuild corners before HPC completion; normal force/integration/ground completion continues. No teleport or frozen-world mode.
- `MotionState.recovery_entry_count`/`recovery_exit_count` are cumulative native diagnostics. `barrier_sector` is -1 on active recovery updates (lookup bypassed). Entry/exit creates no `BarrierImpact` (no direct `00424860` call); an ordinary wall response before entry can still produce its impact. [Damage](contact-effects.md#original-car-damage-presentation) and [contact effects](contact-effects.md) consume ordinary wall contacts; car-to-car and movable-object responses have separate consumers.
- Evidence limits: tested with synthetic chains and a real Donington linked run (head172 exits after 39 direct consumer steps); not an original recording or matched full-physics trace.

## NoQual clutch boundary

- Session consumer calls `Motion::set_start_hold(true)` at NoQual entry, false on release; both idempotent; false without an active hold leaves qualifying gear selection unchanged. `00460170` → `00401320` sets dynamics +0x148 = 1 and gear +0x330 = 0. The open clutch reaches both engine phases (`0040d3b0`/`0040d5f0`): Gas revs the engine while wheel drive stays zero. `0040db10` replaces both axle brake moments with dynamics +0x40 (initialized `0x50000` by `0040a770`) while +0x148 is set. Body not frozen, pedals active. `start_held()` exposes the hold.
- `00448411` → `00401260(0)` closes the clutch: gear1 for automatic local transmission (+0x27c=2; mode0 also); manual (+0x27c=1) keeps neutral or a driver-selected gear (`00418f60` allows F to select1 from0 before/after release). `004524d9` supplies the configured transmission. The source's additional gameplay+0x14 == -1 branch is outside this local-player API.
- `00448130`'s other local write is **not dynamics +0x40**: it addresses launch adjustment `004c5d80[player*4]`. Only config phase +0x5f6=2/4 outside mode2 enables it; ordinary qualifying uses phase1 (no launch adjustment at the first start-line crossing). NoQual hold→release computes the signed adjustment from engine speed +0x124 and maximum +0x20: truncate `max/100` first; below 60% → 0; 60–70% linear 0 → `0x147a`; above 70% linear 0 → `-0x147a` at maximum. Fixed division precedes the final fixed multiplication.
- Before controls each tick, `00422f60` moves the adjustment toward zero by `0x73` (no delta-time multiply) and calls `00412890` to set all eight tire offsets +0xdc..0xf8. Crossing zero runs `00402b90`, restoring `{0,0,0,0,0xccc,0,0,0}` in that field order. Zero initial adjustment leaves initial `0x1eb8` offsets intact. Controls publishes adjustment and eight offsets; Motion consumes front/rear lateral, longitudinal and ellipse shape offsets separately. Gas ramp is the independent +0x120 field. Native decay follows the 25 Hz input-update schedule (not a claim about the original keyboard poll rate).
- `004d37b0=360` is a separate start/AI-route record (`004024c0`/`00403490`, AI consumers), not throttle or clutch.

## Impact caller

- `00409fa0`: the selected contact index chooses the original front/rear representative world position. Strength = source square-root length of `abs(dot(normal,post-contact velocity)) ×16` (kind1) or ×5 (kind0), clamped to one. `00419ad0` guarantees base event kind1 above `0x106`; the caller applies `0xe666` once; the audio adapter then performs `00424860`'s own scaling/sample selection (not a generic crash-volume normalizer).
- Full and distant bodies share this consumer. Distant path: `00444830` clears prior force/moment after movement, before `00409c30` accumulates new `004095b0` moments; `00444ee0` keeps them (next distant update discards, or next full `0040caf0` consumes them before its clear). Damage-cycle advancement applies even below the damage threshold. Distant ground publishes the same cumulative impact count. [Distant barrier comparison](single-race-fleet-reference.md#distant-barrier-response--2026-10-17): all 64 recorded updates incl. three distant contacts match in all three replay modes.
- `BarrierImpact`: position, kind, strength, local-player ownership, barrier index. `MotionState.impacts` = this tick's events; `impact_count` cumulative; `barrier_contact_count` = this tick's physical contacts. The damage consumer adds kinds2/3/4 and node mutations; kind1 stays the guaranteed original call before any extra event; first-contact landings add kind5.
- Reference probe: normal Honda qualifying start, Gas+Left ordinary ticks, first Debug probe hit segment 102 at tick 83, event position `(-8148451,407069,-6246684)`, pre-audio strength 6335 (native observation, not an original recording).
